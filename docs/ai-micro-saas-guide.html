Building a Production AI Micro-SaaS in Python

The complete engineering architecture for shipping profitable AI APIs, data utilities, and developer services with zero infrastructure bloat.

The barrier to creating useful AI functionality has never been lower. However, turning a Python script or Jupyter notebook into a production SaaS that charges customers requires answering four critical engineering questions:

  1. How do you authenticate and rate-limit programmatic API consumers?
  2. How do you handle slow LLM generation requests without blocking the web event loop?
  3. How do you collect recurring subscription revenue or one-off license fees legally across global tax jurisdictions?
  4. How do you package and deploy the entire stack reliably with HTTPS in production?

1. Dual Authentication: Web Sessions vs Developer API Keys

An AI micro-SaaS typically serves two distinct user personas: browser-based dashboard users managing billing, and external developers or automated scripts calling your API endpoints.

PyLaunchpad solves this by decoupling human session authentication from machine API access:

  • Bearer JWT Tokens: Issued upon email/password login, stored in browser cookies or Authorization headers, with automatic expiration (e.g. 7 days).
  • SHA-256 Hashed API Keys: Developers generate API keys in their dashboard (prefixed with pylp_live_...). The plaintext key is shown only once; the database stores only the cryptographic SHA-256 hash. Every request verifies the hash in constant time and tracks request timestamps for sliding-window rate limiting.

2. Handling Slow LLM Requests Without Celery or Redis

Large Language Model calls (e.g. OpenAI GPT-4o, Anthropic Claude, image generation models) often take between 3 and 15 seconds to return a response. If executed synchronously inside a standard web handler, these calls block worker threads and quickly cause server connection exhaustion.

Traditional advice recommends configuring Celery with a Redis message broker. While effective for massive enterprise scale, running Celery and Redis doubles your container memory footprint and introduces significant DevOps failure points.

PyLaunchpad utilizes an in-process asynchronous worker queue powered by Python's native asyncio.Queue. Jobs are submitted from HTTP endpoints without blocking, retried automatically with exponential backoff on transient network failures, and executed cleanly within the existing ASGI process.

3. Turnkey Monetisation with Polar.sh Merchant of Record

The greatest compliance trap for indie builders is international sales tax. Selling digital software directly via standard Stripe Checkout makes the founder personally liable for collecting and filing tax returns in every customer's jurisdiction.

Integrating Polar.sh as a Merchant of Record (MoR) eliminates this liability. Polar handles:

  • Automatic tax rate calculation (EU VAT, Australian GST, US sales taxes).
  • Tax remittance and quarterly filings with international revenue agencies.
  • PCI-compliant Stripe checkout sessions and localized payment methods.
  • Direct automated bank transfers into your bank account.
